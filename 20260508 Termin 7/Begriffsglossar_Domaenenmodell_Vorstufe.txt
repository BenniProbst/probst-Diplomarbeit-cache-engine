ZWECK
  Dieses Glossar identifiziert konzeptionelle Identitaeten zwischen Begriffen,
  die in unterschiedlichen Forschungsarbeiten verschiedene Namen tragen, aber
  funktional dasselbe meinen. Es ist die VORSTUFE zum Domaenenmodell, das
  spaeter (NACH Termin 6 Vollstaendigkeit) als UML in drawio formalisiert wird.

  Trennung:
    DOMAENE 1 = SUCH-ALGORITHMEN     (WAS und WIE wird gesucht)
    DOMAENE 2 = CACHE-ENGINE         (WIE/WO liegen Daten im Cache)
    QUERSCHNITT = METRIKEN/MESSUNG   (gemeinsame Beobachtbarkeit)

  Notation einer Begriffsgruppe:
    [KANON] kanonischer Name fuer PRT-ART
       <- "Synonym 1" (Quelle/Paper)
       <- "Synonym 2" (Quelle/Paper)
    BEDEUTUNG: was der Begriff funktional bezeichnet
    ABGRENZUNG: gegen welchen anderen Begriff er klar getrennt sein muss

1.1  STRUKTURELLE BAUSTEINE EINES TRIE

[KANON] KNOTEN (Node)
   <- "Node"                  (ART, HOT, B²-tree, START, Masstree)
   <- "Vertex"                (Graph-theoretische Sicht, CoCo-trie)
   <- "Decision Node"         (B²-tree: Entscheidungsknoten in der Page)
   <- "Span Node"             (B²-tree: Konsumiert mehrere Bytes)
   <- "Trie Node"             (Jacobson 1989, allgemein)
   BEDEUTUNG: Eine logische Verzweigungseinheit der Suchstruktur.
   ABGRENZUNG: KEIN "Page" — eine Page kann mehrere Knoten enthalten.

[KANON] SEITE / PAGE
   <- "Page"                  (B+-Tree, B²-tree, Masstree)
   <- "Block"                 (Bender et al. 2002 Tree Layout)
   <- "Suchseite"             (PRT-ART Termin 2)
   <- "Page-Cluster"          (CSB+-tree)
   <- "Disk Block"            (klassische DBMS-Sicht)
   BEDEUTUNG: Containereinheit, in der ein oder mehrere Knoten gespeichert
              und aus dem Cache/Speicher als Einheit geladen werden.
   ABGRENZUNG: Cache Line (kleinere Granularitaet, Hardware-Einheit).
              Page in PRT-ART ist Software-Konzept; Cache Line ist Hardware.

[KANON] SEITENTYP / PAGE TYPE
   <- "Page Type"             (PRT-ART Termin 2)
   <- "Node Family"           (ART: Node4/16/48/256)
   <- "Node Layout"           (HOT, B-Trees Are Back)
   <- "Encoding"              (CoCo-trie: Pool unterschiedlicher Encodings)
   <- "Page Format"           (B²-tree)
   BEDEUTUNG: Konkrete Auspraegung einer Seite mit fester Layout-Konvention.
   PRT-ART Familie:
       - Dense-Byte-Page         (analog ART Node256, dichte Byte-Transitionen)
       - Extended Dense Page     (analog START multilevel Nodes)
       - Sparse Patricia Page    (analog HOT, diskriminierende Bits)
       - Redirect-Page           (analog CoCo-trie collapsed macro-nodes)
       - PRT-Custom-Cache-Page   (eigener Beitrag: B²+CSS/CSB+-Schnitt)

[KANON] PFAD / SUCHPFAD
   <- "Search Path"            (allgemein)
   <- "Root-to-Leaf Path"      (Bender/Demaine/Farach-Colton 2002)
   <- "Traversal"              (allgemein)
   <- "Lookup Path"            (CoCo-trie, ART)
   BEDEUTUNG: Sequenz von Knotenbesuchen vom Root bis zum Treffer/Miss.

[KANON] PRAEFIXKOMPRESSION / PFADKOMPRESSION
   <- "Path Compression"       (ART)
   <- "Lazy Expansion"         (ART)
   <- "Patricia Bits"          (HOT, Patricia Trees)
   <- "Discriminative Bits"    (HOT)
   <- "Span"                   (HOT, B²-tree: Bit-/Byte-Span pro Node)
   <- "Prefix Truncation"      (B-Trees Are Back)
   <- "Collapsed Subtrie"      (CoCo-trie macro-nodes)
   BEDEUTUNG: Eindeutige Schluesselsegmente werden NICHT als separate Knoten
              gespeichert, sondern in einem einzigen Knoten/Eintrag kondensiert.
   ABGRENZUNG: Redirect (siehe naechster Eintrag) ist die PRT-ART-spezifische
              physische Umsetzung; Praefixkompression ist das logische Prinzip.

[KANON] REDIRECT
   <- "Macro-Node"             (CoCo-trie)
   <- "Anchor"                 (Wormhole)
   <- "Shortcut Node"          (Wormhole, Redirect-Diskussion)
   <- "Rewiring"               (START)
   <- "Jump Pointer"           (Path-Prefetching ScienceDirect 2024)
   BEDEUTUNG: Knoten, der einen ganzen eindeutigen Restpfad in einem
              einzigen Sprung ueberspringt — physische Umsetzung von
              Praefixkompression in PRT-ART.

[KANON] FANOUT
   <- "Fanout"                 (allgemein, ART, B+-Tree)
   <- "Branching Factor"       (CoCo-trie, klassisch)
   <- "Children Count"         (Jacobson 1989: degree)
   <- "Degree"                 (Jacobson 1989, Graphentheorie)
   BEDEUTUNG: Anzahl der Kinder eines Knotens (wie viele Sub-Trees).

[KANON] HOEHE / TIEFE
   <- "Tree Height"            (allgemein, HOT explizit)
   <- "Depth"                  (Jacobson 1989, allgemein)
   <- "Tree Levels"            (Jacobson 1989, BFS-level)
   BEDEUTUNG: Maximale Pfadlaenge Root -> Blatt; bestimmt Worst-Case-Lookup.

2.3  PREFETCH-KONZEPTE
--------------------------------------------------------------------------------

[KANON] PREFETCH
   <- "Prefetch"               (allgemein)
   <- "Software Prefetch"      (Chen/Gibbons/Mowry 2001, GCC __builtin_prefetch)
   <- "Hardware Prefetch"      (Intel/AMD, automatisch)
   BEDEUTUNG: Daten werden VOR dem tatsaechlichen Bedarf in den Cache geladen.

[KANON] PREFETCH-DISTANZ
   <- "Prefetch Distance"      (PRT-ART, Khan 2011)
   <- "Lookahead Distance"     (Chen/Gibbons/Mowry 2001)
   <- "Prefetch Offset"        (Khan 2011)
   BEDEUTUNG: Zeit-/Pointer-Abstand zwischen Prefetch und tatsaechlichem
              Zugriff. Zu klein -> noch nicht da; zu gross -> Cache Pollution.

[KANON] OVERFETCH / CACHE POLLUTION
   <- "Overfetch"              (PRT-ART Termin 4)
   <- "Cache Pollution"        (Mahling 2025, allgemein)
   <- "False Prefetch"         (Naderan-Tahan 2016)
   BEDEUTUNG: Prefetch laedt Daten, die NICHT verwendet werden, und
              verdraengt nuetzliche Cachelines.

[KANON] FILL BUFFER
   <- "Fill Buffer"            (Intel uarch, Mahling 2025)
   <- "Line Fill Buffer (LFB)" (Intel)
   BEDEUTUNG: Hardware-Puffer, der ausstehende Cache-Misses bedient.
              Begrenzte Anzahl -> bestimmt Prefetch-Wirksamkeit.

[KANON] HOT PATH
   <- "Hot Path"               (Dortmund 2023 Cache-Optimization)
   <- "Frequent Access Path"   (Path-Prefetching ScienceDirect 2024)
   <- "Probability-driven Layout" (Bender/Demaine 2002)
   BEDEUTUNG: Pfad, der mit hoher Wahrscheinlichkeit besucht wird;
              Kandidat fuer physische Zusammenfuehrung im Cache.

NOCH UNGEKLAERTE/UNAUFGELOESTE BEGRIFFE (TODO fuer Termin 7+)

  Mapping zu CoCo-trie Macro-Node noch unklar

  noch zu ueberpruefen

  Synchronisations-Begriffe noch nicht vollstaendig harmonisiert
* SuRF "Fast Succinct Trie (FST)" + "LOUDS-Dense / LOUDS-Sparse" —
  Mapping zu PRT-ART Seitentyp-Familie (Dense vs Sparse) noch zu pruefen!
  -> Diese Konzepte stehen sehr nah an PRT-ART Dense-Byte-Page und
     Sparse Patricia Page; SuRF + Jacobson 1989 muessen vor Termin 8
     in Domaenenmodell integriert werden.
