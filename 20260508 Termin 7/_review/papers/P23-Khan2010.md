**Voller Titel:** Data Cache Prefetching With Dynamic Adaptation
**Autor:** Minhaj Ahmad Khan (Bahauddin Zakariya University, Multan, Pakistan)
**Venue:** Computer Journal Oxford, Vol 54 No 5, 2010 (Online ePub Maerz 2010, Print 2011)
**Volltext:** `_text/P23-Khan2010.txt` (9 Seiten, 39 KB)

## 1. Konzeptionelle Identitaet

**Runtime-adaptiertes Software-Prefetching** via dynamischen Code-Spezializer. Erzeugt zur Compile-Zeit Code-Templates mit Prefetch-Offsets, die zur Runtime angepasst werden.

> "We present an approach that is able to generate accurate prefetch instructions by exploiting information available at runtime. The code is instrumented with prefetches having offsets which may be adapted at runtime through a dynamic code specializer." (P23:S.1/19-22)

**Klasse:** Runtime-adaptive Software-Prefetching-Strategie
**Performance:** ~2.5% Average Speedup auf Itanium-II (icc/gcc)

## 2. Hauptkonzept

### Prefetch-Distance Problem

> "The prefetch distance mainly depends upon the latency of cache miss and the latency of the loop iteration [...]. The latency of the loop iteration cannot be determined (statically) at compile time and, therefore, it results in inaccurate prefetching of data." (P23:S.1/52-58)

### Loesung: Template + Specializer

1. **Compile-Time:** Code mit `lfetch (&X[i+offset])` instrumentieren, mehrere Versionen mit verschiedenen Offsets kompilieren
2. **Compile-Time:** Eine Version als **Template** waehlen, **Specializer-Code** generieren, der Offset-Slots mit neuen Werten fuellen kann
3. **Runtime:** Loop-Latenzen messen, Specializer aktiviert, Offset im Template angepasst

→ Sehr geringer Runtime-Overhead (nur wenige Instructions modifiziert).

## 3. Schlüssel-Algorithmus (P23:Sec.3)

1. **Compile-Time-Analyse**: Identifiziere Candidate-Variables
2. **Cost-Benefit**: Dynamic Prefetching nur wenn Cache-Miss-Latency > Runtime-Overhead
3. **Code-Instrumentierung**: Prefetch-Instructions + Specializer-Call einfuegen
4. **Template-Wahl + Specializer-Generierung**
5. **Runtime**: Loop-Latency messen, Specializer aktivieren

## 6. Kernanschluss fuer PRT-ART

Khan 2010 zeigt: **Prefetching kann zur Runtime adaptiert werden** durch lightweight Code-Modifikation. PRT-ART Cache-Engine sollte:
1. **Cost-Benefit-Analyse** durchfuehren (vgl. START Cost Model P05)
2. **Prefetch-Distanz dynamisch anpassen** (statt fix)
3. **Sehr kleinen Runtime-Overhead** aufweisen

Khan ist damit ein **methodischer Baustein** fuer die PRT-ART Cache-Engine Modus 3 (online adaptiv).
