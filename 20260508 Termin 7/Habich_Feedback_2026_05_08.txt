H5 — CacheEngine als ABI-stabiler Production-Container
================================================================================

ANFORDERUNG
   Nach Abschluss der Experimente liefert die CacheEngine fuer eine
   Plattform die beste Suchalgorithmus-Rekombination unter Optimierung.
   Diese Optimal-Wahl wird ABI-stabil geladen + ueber std::map<>-aehnliches
   Interface in Produktion verfuegbar.

ARCHITEKTUR (Praezisierung der bisherigen F12-K)
   Experiment-Modus (Diplomarbeit-Toolchain)
      → CacheEngineBuilder iteriert ueber Permutationen
      → Findet best-permformende Algorithmus-Permutation pro Plattform
      → Persistiert die Optimal-Wahl als "Production-Konfiguration"

   Production-Modus (ComdareDB-Verwendung)
      → CacheEngineBuilder als Container-Library
      → Laedt Optimal-Konfiguration der Plattform (ABI-stabil)
      → Bietet std::map-API fuer den Konsumenten

GOOGLE-TEST-INTEGRATION
   Experiment-Loops nutzen Google Tests mit eingeschalteter Mess-Logik
   (Template-Pattern Mess-Tool). Das gleiche Test-Setup wird in Produktion
   als Verifikations-Suite mitgeliefert (ohne Mess-Aktivierung).

ZIEL
   Eine Library, die im Experiment der Diplomarbeit den besten Algorithmus
   findet und in der Produktion (ComdareDB spaeter) den besten Algorithmus
   ueber ein std::map-API anbietet.

F3 — SDSL-Library
   ENTSCHEIDUNG (c-erweitert)  SDSL-Library als C++23-Portierung in eigener
                                Bibliothek.
   PRAEZISIERUNG  SDSL ist C++11 (vor KI-Zeit). C++23-Metaprogrammierung
                  ermoeglicht compile-time-optimierte Datenstrukturen, die
                  je Plattform/ISA optimal kompiliert werden. Mit der
                  CacheEngine-Awareness koennen wir bessere Ergebnisse als
                  SDSL liefern.
   STRATEGIE     SDSL-Lite kopieren → Auf C++23 portieren → Erweiterung mit
                 Compile-Time-ISA-Optimierungen (BMI2 popcnt, AVX-512
                 broadcast, ARM SVE/SVE2). Vermeidet Latenz-sensible
                 Runtime-Konstrukte.
   FOLGE         Neue Komponente `comdare-succinct/` (oder unter
                 `prt_art/legacy_reimpl/SDSL-Cpp23-Port/`). Aufwaendige
                 Portierungs-Aufgabe — eigene Task.

F4 — HBM-Allocation-API
   ENTSCHEIDUNG (b+c)  Plattform-spezifisch via Abstract Factory + Hybrid-
                       Cache-Hierarchie-Manager.
   PRAEZISIERUNG  Software-Cache-Hierarchie ueber DIMM + HBM:
                  • CacheEngine verwaltet Mix in Software (Adapter +
                    Scheduler + Engine)
                  • Abstract Factory Pattern fuer plattform-spezifische
                    Hardware-Bindung
                  • Compile-Time durch Metaprogrammierung — passt zur
                    CacheEngineBuilder-Praecompile-Mechanik
                  • Plattform-Adapter:
                      - IntelHBMAllocator (`hbwmalloc`)
                      - GraceHopperHBMAllocator (CUDA/UCM-API)
                      - StandardDIMMOnlyAllocator (Fallback)
   FOLGE         Neue Concept-Achse: `IHBMAllocator` mit Plattform-
                 Implementations. Cache-Hierarchie-Manager als neue
                 Komponente in `cache_engine/subsystems/cache_hierarchy_manager/`.

F5 — Datasets-Generator
   ENTSCHEIDUNG (a, KORRIGIERT)  Original Java-YCSB einbinden, Steuerung
                                  via CMake + sh/bat-Skripte (NICHT Python).
   FOLGE         Java-YCSB ist Prerequisite (JVM noetig); aber kein Python.
                 Auf Talos OS muss Java-Runtime separat bereitgestellt
                 werden — wird im Compiler-Provisioning mitberuecksichtigt.

F6 — Zipfsche Theta-Werte
   ENTSCHEIDUNG (c)  Vier Klassen: 0.0 (uniform Baseline), 0.5, 0.99, 1.5.

F7 — Mixed-Length-Verteilung

   FOLGE         Datasets-Permutations-Achse erweitert um "Schluessel-
