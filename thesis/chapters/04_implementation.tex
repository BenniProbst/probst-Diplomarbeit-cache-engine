\chapter{Implementation}\label{ch:implementation}

\section{Drei-Repo-Architektur}

Die Implementation ist auf drei Git-Repositorien verteilt
(User-Direktive 2026-05-13/14, dokumentiert in
\texttt{STRUCTURAL\_CORRECTION\_diplomarbeit.md} \S{}11.5):

\begin{itemize}
    \item \texttt{comdare-cache-engine} — \textbf{WIE} gemessen wird
          (Werkzeug, Mess-Mechanik, SOTA-Bibliothek)
    \item \texttt{comdare-prt-art} — \textbf{Pruefling} (PRT-ART
          + 14 Pruefling-Re-Implementations P11--P27)
    \item \texttt{probst-Diplomarbeit-cache-engine} — \textbf{WAS}
          getestet wird (XML-Configs der drei Messreihen, messung\_driver,
          Auswertungs-Pipeline, Manuskript)
\end{itemize}

\section{cache-engine (Werkzeug)}

Wesentliche Komponenten:

\begin{description}
    \item[Builder] \texttt{cache\_engine/builder/} — XML-Config-Parser
          (V8.6 mit \texttt{AlgorithmProfile}-Loader), Codegen
          (V9.3 \texttt{generate\_module\_from\_profile}), Permutations-
          Loop, Module-Loader (LoadLibrary/dlopen), ExperimentDriver
          (V8.7 + V10.5 + V10.6 + V11.2 + V13.2 + V13.3 mit
          7 Phasen + 2 opt-in-Phasen).
    \item[ABI] \texttt{cache\_engine/include/cache\_engine/abi/} —
          \texttt{search\_engine.hpp} (V12.3 mit contains/count/find/clear),
          \texttt{execution\_engine.hpp} (V8.5 mit ResultAggregator-Member
          bei \texttt{COMDARE\_EXPERIMENT\_MODE\_ON}),
          \texttt{baustein\_variants.hpp} (V9.2 + V11.4 + V12.6: 11~Achsen,
          $\sim$80~Tag-Strukturen mit description+paper\_ref),
          \texttt{resolve\_baustein.hpp} (V10.2 operationalisiert).
    \item[algorithm\_profiles/sota] 30 SOTA-Profile als XML
          (8~Tier-1 V8.3 + 22~Tier-2/3 V9.5).
    \item[Tests] 6~Codegen-Roundtrip-Tests (V10.4 \texttt{test\_codegen\_from\_profile})
          + 10~ExperimentDriver-V13-Tests (V14.2
          \texttt{test\_experiment\_driver\_v13}).
\end{description}

\section{prt-art (Pruefling)}

\begin{description}
    \item[hybride API] \texttt{prt\_art/identity/PrtArtSearchEngine} —
          1~Param $\Rightarrow$ Vector-API (V12.1 vollstaendig), 2~Params
          $\Rightarrow$ Map-API (V12.2 + V13.5 mit merge/extract
          vollstaendig), $N>2$ $\Rightarrow$ Tuple-API.
    \item[Adapter] \texttt{PrtArtSearchEngineAdapter\{Map,Vector,Tuple\}}
          mit V12.4 ABI-Erweiterung + V11.1 notify\_*-Verdrahtung an
          DensityTracker, PathOrientedPrefetch, HypothesisMetrics.
    \item[Komponenten] 4+2 Allocator-Pools, OLC mit reservierten Bloecken,
          MultiLevelLayout, PathOrientedPrefetch, DensityTracker,
          HypothesisMetrics (H1/H2/H3).
    \item[legacy\_reimpl] 14 Pruefling-Re-Implementations
          (V9.4 verschoben aus cache-engine, V10.1 cache-engine-Variante geloescht).
    \item[Tests] 66 Tests (V14.1: 51~alte + 15~neue fuer V12+V13 API).
\end{description}

\section{Diplomarbeit/Code (Anwender)}

\begin{description}
    \item[messung\_driver] 3-Reihen-Loop oder \texttt{--messreihen-xml=FILE}
          Mode (V9.6 + V11.3) mit \texttt{COMDARE\_EXPERIMENT\_MODE\_ON}
          Compile-Check (V8.12).
    \item[experiment\_config] 3~XMLs fuer Messreihen A/B/C
          (V8.13 defined/full Mode) plus
          \texttt{messreihen.xml}-Standard-Template (V11.5).
    \item[Auswertungs-Pipeline] \texttt{binary\_to\_csv} $\Rightarrow$
          \texttt{csv\_to\_latex} (mit Algorithmus-Steckbrief) $\Rightarrow$
          \texttt{diagram\_generator} (TikZ, A4-aware) $\Rightarrow$
          \texttt{latex\_to\_pdf}.
    \item[CI] \texttt{.gitlab-ci.yml} (primaer) + \texttt{.github/workflows/ci.yml}
          (synchron) in alle 3~Repos (V11.7 + V14.3 Test-Discovery-Workaround).
\end{description}
