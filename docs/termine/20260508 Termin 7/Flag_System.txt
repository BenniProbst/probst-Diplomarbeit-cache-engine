ZWECK
   Strukturierter Identifier-Mechanismus fuer Such-Algorithmus-Modul-
   Permutationen, nach Vorbild der Intel-CPUID-Feature-Flags.
   Ersetzt den vorherigen `perm_id`-Hash.

DESIGN-PRINZIP (Intel-CPUID-Analogie)
   • Pro Bausteine-Achse eine "Bank" (uint64_t)
   • Pro Implementation eine eindeutige Bit-Position
   • Eine Permutation = Vereinigung der gesetzten Flags
   • Pro Achse genau ein Bit (statisch); mehrere Bits bei dynamischen
     Bausteinen (z.B. DynamicValueHandle erlaubt mehrere Handle-Varianten)
   • Wohl-geordnete Reihenfolge der Banken im Identifier-String

QUELLEN-RECHERCHE
   • CPUID — CPU Identification: https://www.felixcloutier.com/x86/cpuid
   • CPUID Wikipedia: https://en.wikipedia.org/wiki/CPUID
   • Intel Architecture Instruction Set Extensions PDF
   • Linux Kernel x86 Feature Flags: https://docs.kernel.org/arch/x86/cpuinfo.html

================================================================================
SCHEMA-UEBERSICHT (9 Banken)
================================================================================

   Bank 1  PageBank          uint64_t (64 Bits fuer Page-Type-Implementations)
   Bank 2  NodeBank          uint64_t (64 Bits fuer Node-Type-Implementations)
   Bank 3  TraversalBank     uint64_t (64 Bits fuer Traversal-Algorithmen)
   Bank 4  ValueHandleBank   uint64_t (Bits fuer ValueHandle-Strategy)
   Bank 5  MemoryLayoutBank  uint64_t (Bits fuer MemoryLayout)
   Bank 6  AllocatorBank     uint64_t (Bits fuer Allocator-Strategy)
   Bank 7  PrefetchBank      uint64_t (Bits fuer Prefetch-Strategy)
   Bank 8  ConcurrencyBank   uint64_t (Bits fuer Concurrency-Disziplin)
   Bank 9  IsaBank           uint64_t (Bits fuer ISA-Pfad)

   Total: 9 x uint64_t = 72 Bytes pro Permutation-Identifier
   (analog zu CPUID: mehrere Banken, jede mit eigenen Bit-Positionen).

================================================================================
PERMUTATION-IDENTIFIER STRUCT
================================================================================

struct PermutationFlags {
  std::uint64_t page_bank;
  std::uint64_t node_bank;
  std::uint64_t traversal_bank;
  std::uint64_t value_handle_bank;
  std::uint64_t memory_layout_bank;
  std::uint64_t allocator_bank;
  std::uint64_t prefetch_bank;
  std::uint64_t concurrency_bank;
  std::uint64_t isa_bank;

  // Wohl-geordnete Identifier-String-Repraesentation
  constexpr std::string to_identifier() const noexcept;

  // Operatoren
  constexpr bool operator==(PermutationFlags const&) const noexcept = default;
  constexpr auto operator<=>(PermutationFlags const&) const noexcept = default;
};

IDENTIFIER-FORMAT
   "<page_flag>.<node_flag>.<traversal_flag>.<value_handle_flag>.
    <memory_layout_flag>.<allocator_flag>.<prefetch_flag>.
    <concurrency_flag>.<isa_flag>"

BEISPIEL (ART-Original auf Sapphire Rapids x86_64 + AVX-512)
   "PAGE_DENSEBYTE_ART256.NODE_NODE256.TRAVERSAL_BYTEBYBYTE.
    VALUEHANDLE_INLINE.MEMORY_CACHELINE_ALIGNED.ALLOCATOR_POOL_PER_PAGETYPE.
    PREFETCH_NONE.CONCURRENCY_OLC|MEMORY_READ_DISC.
    ISA_SCALAR_X86_64|X86_AVX512F|X86_BMI2"

CONSTRAINTFILTER-IMPLEMENTATION (CMake compile-time)
================================================================================

// Beispiel: AVX-512 nur auf Targets mit entsprechender Hardware
constexpr std::uint64_t allowed_isa_visionfive2 =
    IsaBank::SCALAR_RISCV | IsaBank::RISCV_V;

constexpr std::uint64_t allowed_isa_pi5 =
    IsaBank::SCALAR_ARM64 | IsaBank::ARM_NEON;

constexpr std::uint64_t allowed_isa_grace_hopper =
    IsaBank::SCALAR_ARM64 | IsaBank::ARM_NEON |
    IsaBank::ARM_SVE | IsaBank::ARM_SVE2;

constexpr std::uint64_t allowed_isa_sapphire_rapids =
    IsaBank::SCALAR_X86_64 | IsaBank::X86_SSE2 | IsaBank::X86_SSE4_2 |
    IsaBank::X86_AVX | IsaBank::X86_AVX2 | IsaBank::X86_AVX512F |
    IsaBank::X86_AVX512BW | IsaBank::X86_AVX512VL | IsaBank::X86_BMI1 |
    IsaBank::X86_BMI2 | IsaBank::X86_AESNI;

template<TargetPlatform T>
constexpr bool is_permutation_valid(PermutationFlags const& p) noexcept {
  if constexpr (T == TargetPlatform::VisionFive2) {
    return (p.isa_bank & ~allowed_isa_visionfive2) == 0;
  }
  // ... weitere Targets
}

================================================================================
USAGE-FLOW
================================================================================

1. CMake-Codegen (`tools/permutation_codegen/codegen.cmake`) + sh/bat-Helper
   (REVIDIERT durch H6 — NO-PYTHON-DIREKTIVE; Talos OS hat kein Python)
   - Enumeriert alle Kombinationen der Flag-Banks via CMake `foreach`
   - Wendet ConstraintFilter an (Bit-Maskierung) per CMake-Funktionen
   - Generiert pro gueltige Permutation via `configure_file()` + `add_custom_command()`:
       - .cpp-Datei (Schalen-Code mit den Bausteinen)
       - .ccm Modul-Interface
       - CMake `add_library(perm_<flags> ...)` Target
   - Wo CMake-Logik nicht ausreicht: shell-Skripte (`codegen.sh` + `codegen.bat`,
     synchron gepflegt)
   - Falls komplexe Logik unausdrueckbar: minimaler kompilierter C++23-Helper
     im BuildSystem

2. CMake-Build
   - Includiert `build/generated/permutations.cmake`
   - Parallelisiert die Hunderten Targets
   - Pro Target: Schale (C++23) + Bausteine (Original-Compiler) → .so/.dll

3. CacheEngineBuilder (Runtime)
   - Scannt `build/modules/` nach existierenden Permutationen
   - Iteriert ueber Module: dlopen, Experiment, dlclose
   - Identifiziert Module per `PermutationFlags::to_identifier()`
