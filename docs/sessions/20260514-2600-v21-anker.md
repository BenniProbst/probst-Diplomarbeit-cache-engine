### V21.1 Strategie — ext-Verdrahtung-Skelett (nicht-blockierend)
Das `art_body.hpp.template` bekommt einen optionalen `#if defined(COMDARE_HAVE_UNODB)`-Block, der `unodb::db<Key, Value>` instanziiert und 3 Operationen (insert/get/remove) wrapper. Default-Path bleibt der V17.2 Stub.

```cpp
#if defined(COMDARE_HAVE_UNODB)
    // V21.1: Optionale ext/-Verdrahtung
    // Spaetere Aktivierung via CMake-Flag + ext/P01-ART/unodb Build-Integration
    #include <unodb/art.hpp>
    using ext_db_t = unodb::db<std::uint64_t, std::uint64_t>;
#endif
```

**Begruendung:** Vorbereitet, aber nicht erzwungen. Spaetere Aktivierung
via CMake-Flag + Lizenz-Pruefung mit User (Apache 2.0 OK, aber GitLab-Push
braucht ggf. NOTICE-Update).

### V21.3 Strategie — Sample-Mess-Daten
Mess-Daten-Generator generiert N=10 Permutationen mit:
- 6 SOTA-Profile (art, hot, masstree, coco_trie, btreesareback, surf)
- 3 prtart-Varianten
- 1 baseline (HOT)
Pro Permutation pseudozufaellige Werte fuer alle V20-Felder
(workload_used + Mess-Counter). Auswertung kann sofort starten,
bevor V21.2 echte HW liefert.
