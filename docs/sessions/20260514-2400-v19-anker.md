## §2 V19-Designentscheidung

### Habich-Termin-8-Diskussionspunkt 3.3 (Workload-Routing-Heuristik)
V11.2 routet aus dem `traversal`-Tag: heuristisch, aber jeder Algorithmus
hat seine bevorzugte Mess-Workload, die nicht immer mit traversal
korreliert (z.B. SuRF ist Range-Filter aber profitiert von YCSB-A
Reads + Updates fuer adaptive Filter-Updates).

**Loesung:** Profile-XML kann optional `<expected_workload>` Tag setzen,
der die V11.2-Heuristik ueberschreibt:

```xml
<comdare_algorithm_profile id="surf">
  ...
  <axes>...</axes>
  <expected_workload>YCSB_A</expected_workload>
  <key_value_signature>...</key_value_signature>
</comdare_algorithm_profile>
```

### Override-Reihenfolge (V19.3)
1. **expected_workload aus Profile** (V19.3, hoechste Prioritaet)
2. **traversal-Heuristik** (V11.2, Fallback bei fehlendem Tag)
3. **Default-WorkloadOptions** (V11.2, Module ohne Profile)
