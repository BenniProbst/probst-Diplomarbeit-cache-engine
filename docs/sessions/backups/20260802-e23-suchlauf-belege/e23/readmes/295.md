# comdare-isa-dispatch

**Module Version:** 1.0 (V41.E4 + Doku 25 Befüllung, 2026-06-01)

## Scope

`comdare-isa-dispatch` ist eine spezialisierte Hardware-Abstraktions-Bibliothek für CPU-ISA-Dispatch, SIMD-Extensions und Plattform-Profile. Sie bietet eine **header-only, Compile-Time-polymorphe API** zur Konfiguration von Permutationsräumen im Cache-Engine-Framework und in anderen hochperformanten Anwendungen.

Das Modul konzentriert sich auf **drei orthogonale Hardware-Achsen**:
- **Achse 09 (axis_09_isa):** Haupt-CPU-ISAs (x86_64/AMD64, ARM64/Aarch64, RISC-V, PowerPC)
- **Achse 09b (axis_09b_simd_extension):** SIMD/Accelerator-Extensions (NoExt, SSE2–SSE4.2, AVX/AVX2, AVX-512 mit 15 Sub-Flags, NEON, SVE2, RVV, CUDA GH200)
- **Achse 12 (axis_12_general_hardware):** Plattform-Profile (Generic, x86_64, ARM64)

Mit **Cross-Axis-Constraints** (R5.C.3, #704): Eine ISA×SIMD-Extension ist nur mit kompatiblen CPU-Familien kombinierbar (z.B. AVX-512 nur mit x86_64, NEON nur mit ARM). Eine ISA läuft nur auf Plattformen ihrer Familie. Physisch unmögliche Permutationen werden zur Compile-Time gefiltert.

## Monolith-Inventar

Alle 18 definierten Headers sind echte, produktive Dateien aus dem Cache-Engine-Monolith (`libs/cache_engine/`). Sie sind in zwei Subtrees organisiert:

### axes/ — Haupt-ISA (Achse 09) — 10 Header
- `axes/simd/axis_09_isa_strategy_base.hpp` — CRTP-StrategyBase für ISA-Implementierungen
- `axes/simd/concepts/axis_09_isa_concept.hpp` — IsaStrategy-Concept (is_64bit, cpu_family, supports_native_simd)
- `axes/simd/concepts/axis_09_isa_cache_engine_permutation_concept.hpp` — Permutations-Trait
- `axes/simd/axis_09_isa_registry.hpp` — Zentrale Registrierung (EnabledIsas)
- `axes/simd/axis_09_isa_amd64.hpp` — x86_64/Intel64-Implementierung
- `axes/simd/axis_09_isa_aarch64.hpp` — ARM64-Implementierung
- `axes/simd/axis_09_isa_riscv.hpp` — RiscV64-Implementierung
- `axes/simd/axis_09_isa_powerpc.hpp` — PowerPC64LE-Implementierung
- `axes/simd/axis_09_isa_subaxes_is1_to_is3.hpp` — Für Subachsen-Tagging
- `axes/simd/axis_09_isa_flags.hpp` — CMake-generierte Aktivierungsflags

### topics/hardware/ — SIMD-Extensions + Platform — 8 Header
- `topics/hardware/concepts/topic_hardware_concept.hpp` — HardwareComponent-Concept (Marker)
- `topics/hardware/topic_hardware_config_set.hpp` — Topic-Registry mit ISA×SIMD×Platform CartesianProducts + Cross-Constraints
- `topics/hardware/axis_09b_simd_extension/axis_09b_simd_extension_strategy_base.hpp` — CRTP-Base mit vollständigen SSE/AVX/AVX-512-Schichten (15 Flags)
- `topics/hardware/axis_09b_simd_extension/concepts/axis_09b_simd_extension_concept.hpp` — SimdExtensionStrategy-Concept
- `topics/hardware/axis_09b_simd_extension/concepts/axis_09b_simd_extension_cache_engine_permutation_concept.hpp` — Permutations-Trait
- `topics/hardware/axis_09b_simd_extension/axis_09b_simd_extension_registry.hpp` — Zentrale Registrierung (EnabledExtensions)
- `topics/hardware/axis_12_general_hardware/axis_12_general_hardware_strategy_base.hpp` — CRTP-Base für Plattform-Profile
- `topics/hardware/axis_12_general_hardware/concepts/axis_12_general_hardware_concept.hpp` — GeneralHardwareStrategy-Concept
- `topics/hardware/axis_12_general_hardware/concepts/axis_12_general_hardware_cache_engine_permutation_concept.hpp` — Permutations-Trait
- `topics/hardware/axis_12_general_hardware/axis_12_general_hardware_registry.hpp` — Zentrale Registrierung (EnabledPlatforms)

### Nicht im Modul enthalten (nur Monolith-intern)
- Konkrete Implementierungen: amd64.hpp, avx512.hpp, neon.hpp, etc. (sind Wrapper, keine Interfaces)
- Flags-Header (CMake-generiert): axis_09_isa_flags.hpp, axis_09b_simd_extension_flags.hpp, etc.
- Subachsen-Detail: axis_09_isa_subaxes_is1_to_is3.hpp (interner Struct-Tag)
- Hardware-Profile-Implementierungen: generic.hpp, x86_64.hpp, aarch64.hpp

## Leitfaden für Migrationen

### Phase 1 (aktuell): Monolith + Modul-Spiegel
- Cache-Engine **bleibt unverändert** — `libs/cache_engine/` und `libs/cache_engine/topics/hardware/` sind 1:1 die Quelle der Wahrheit.
- Modul-Repo `modules/comdare-isa-dispatch/` ist ein **reiner Kopie-Spiegel** der öffentlichen Interfaces.
- Consumer (im Monolith) nutzbar via `#include <comdare-isa-dispatch/...>` (nach CMake-Dependency-Link).
- **Build-Impact:** Keiner. Monolith-Builds sind unabhängig vom Modul-Repo; beide liegen nebeneinander.

### Phase 2 (Folgephase, Doku 25): Konsumption via DependencyManager
- Modul wird in ein separates Git-Repo / external dependency konvertiert.
- Cache-Engine wechselt von lokalen Includes (`#include <axes/simd/...>`) zu Modul-Includes (`#include <comdare-isa-dispatch/...>`).
- Modul wird über DependencyManager / find_package(comdare-isa-dispatch) geladen.
- **Build-Impact:** Dependency-Graph wird neu strukturiert; Monolith und Modul sind logisch getrennt, aber über CMake verlinkt.

### Migrationsrichtlinie
1. **Kein Bruch aktuell.** Monolith bleibt grün; das Modul ist eine echte, aber noch interne Kopie.
2. **Headers sind header-only.** Keine Abhängigkeit auf kompilierte `.a` / `.so`-Dateien.
3. **Interface ist stabil:** Die Concepts und StrategyBase-Klassen sind das öffentliche Vertragswerk. Implementierungen (konkrete ISA-Wrapper) sind Vendoring und können lokal variieren.
4. **CMake-Schnittstelle:** `target_link_libraries(my_app PUBLIC comdare::isa-dispatch)` liest `include/comdare-isa-dispatch/` zur Compile-Zeit.

## Architektur-Highlights

### CRTP-Pattern (Stateless Polymorphism)
Alle Strategy-Bases (`IsaStrategyBase<Derived>`, `SimdExtensionStrategyBase<Derived>`, `GeneralHardwareStrategyBase<Derived>`) nutzen Curiously Recurring Template Pattern, um Dispatch ohne V-Tables zur Compile-Zeit durchzuführen:
```cpp
class Amd64Isa : public IsaStrategyBase<Amd64Isa> {
    static constexpr bool is_64bit() { return true; }
    static constexpr std::string_view cpu_family() { return "x86_64"; }
    // ...
};
```

### Compile-Time-Concepts
Jede Achse definiert ein Concept (z.B. `IsaStrategy`, `SimdExtensionStrategy`, `GeneralHardwareStrategy`), das die Pflicht-API erzwingt. Der Monolith nutzt `static_assert` in den Konstruktoren der Strategy-Bases, um nicht-konforme Abweichungen sofort zu erkennen.

### Cross-Axis-Constraints via boost::mp11
Das TopicConfigSet nutzt Template-Metaprogrammierung (Boost.MP11), um physisch unmögliche Kombinationen zur Compile-Time auszufiltern:
- **IsaSimdIncompatible:** AVX-512 nur x86_64, NEON nur ARM, etc.
- **IsaPlatformIncompatible:** x86_64-ISA nur auf x86_64-Plattform, etc.
- **Filtered vs. Cartesian:** Rohprodukt ist erhältlich (Diagnose), aber produktive Permutationen sind gefiltert.

## Header-Abhängigkeiten

Das Modul benötigt (extern):
- `<boost/mp11.hpp>` — Boost.MP11 für Metaprogrammierung
- `<concepts>`, `<string_view>`, `<cstddef>`, `<array>`, `<type_traits>` — Standard C++20+

Interne Abhängigkeiten (innerhalb des Moduls):
- `topic_hardware_concept.hpp` — Basis-Marker für alle Hardware-Komponenten
- Strategy-Bases → Concepts (jeweils gegenseitige Validierung im Konstruktor)
- Registries → Wrapper-Klassen (CompileTime-Filter via is_enabled)

## Kuratiertes Header-Set

Die 18 öffentlichen Header repräsentieren:
1. **Konzept-Schicht** (4 Header): Core-Definitionen von HardwareComponent, IsaStrategy, SimdExtensionStrategy, GeneralHardwareStrategy
2. **Abstraktions-Schicht** (4 Header): Strategy-Bases (CRTP-Gerüste)
3. **Permutations-Schicht** (3 Header): Registries (EnabledIsas, EnabledExtensions, EnabledPlatforms) + TopicConfigSet (Cross-Constraints)
4. **ISA-Familie-Schicht** (4 Header): Vier konkrete ISA-Implementierungen (amd64, aarch64, riscv, powerpc)

Absichtlich **nicht** enthalten:
- SIMD-Konkretisierungen (avx512.hpp, neon.hpp, etc.) — sind Implementierungsdetail, kein Interface
- Sub-Achsen-interne Tagging-Header — nur im Monolith-Kontext nötig
- Flags-Header — CMake-generiert, nicht öffentlich
- Platform-Profile-Implementierungen — konkrete Hardware-Definitionen

## Nutzungsbeispiel

```cpp
#include <comdare-isa-dispatch/topic_hardware_config_set.hpp>
#include <comdare-isa-dispatch/axis_09_isa/registry.hpp>
#include <comdare-isa-dispatch/axis_09b_simd_extension/registry.hpp>

using namespace comdare::cache_engine::hardware;

// Compile-Time Registries (gefiltert nach enabled-Flags)
using EnabledIsas = simd::EnabledIsas;  // z.B. [Amd64Isa, Aarch64Isa, RiscVIsa, PowerPcIsa]
using EnabledExts = axis_09b_simd_extension::EnabledExtensions;  // z.B. [NoExt, Sse2, Avx2, Avx512, Neon]
using EnabledPlatforms = axis_12_general_hardware::EnabledPlatforms;  // z.B. [Generic, X86_64, Aarch64]

// Cross-Constraints sind im TopicConfigSet encodiert
static_assert(TopicConfigSet::isa_simd_compatible<Amd64Isa, Avx512SimdExtension>());
static_assert(!TopicConfigSet::isa_simd_compatible<Amd64Isa, NeonSimdExtension>());  // NEON nur ARM
```
