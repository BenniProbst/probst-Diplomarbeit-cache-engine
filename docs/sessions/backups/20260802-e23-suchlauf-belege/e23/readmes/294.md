# comdare-cache-engine-core

**Header-only interface library** exposing the foundational architecture of the COMDARE cache engine framework.

## Scope

This module provides the **CORE DOMAIN** interfaces for building, analyzing, and composing cache engine implementations:

- **Anatomy Framework**: Base abstractions for cache engine "species" (SearchAlgorithm, Sequence, Set, Adapter, View)
- **Execution Engine**: Root abstraction layer for all measurable computation engines (anatomy-based or virus-based)
- **ABI Module System**: Runtime factory patterns for dlopen-based module loading and dynamic composition
- **Compositions**: Known reference implementations (ART, HOT, START, SURF, Wormhole, MassTree)
- **Builder Utilities**: Code generation and permutation tooling for anatomy-based engines

**NO implementation details** — only public interfaces and factory contracts. This is the **definition layer** for cache engine topology and composition patterns.

## Monolith Inventory

This module mirrors the following layers from the monolith (`libs/cache_engine/`) into a standalone, reusable module:

### Anatomy Layer (libs/cache_engine/anatomy/)
Core abstractions for cache engine "gattungen" (biological classification):
- `anatomy_base.hpp` — Two-tier architecture (AnatomyConcept + IAnatomyBase virtual interface)
- `abi_adapter.hpp` — Bridge between compile-time concepts and runtime ABI
- `observable_tier.hpp` — Observer pattern for measurable tier behavior
- `rollbackable_tier.hpp` — State rollback capability for tier state machines
- `scannable_tier.hpp` — Iteration/traversal over tier contents
- `memento_aggregate.hpp` — State capture and restoration for composite structures
- `observer_aggregate.hpp` — Multi-observer composition and broadcast
- `known_algorithms.hpp` — Enumeration of recognized core algorithms

### Execution Engine Layer (libs/cache_engine/execution_engine/)
Root abstraction hierarchy:
- `execution_engine_base.hpp` — ExecutionEngineKind (Anatomy/Virus/Hybrid) + IExecutionEngine interface

### ABI Module System (libs/cache_engine/include/cache_engine/abi/)
Runtime dynamic loading and composition:
- `anatomy_module_abi_v1_decl.hpp` — Lightweight ABI declarations (version/magic/factory signatures)
- `anatomy_module_abi_v1.hpp` — Full ABI including adapter templates and permutation macros
- `module_loader.hpp` — dlopen/dlsym helper and module lifecycle

### Compositions Reference Layer (libs/cache_engine/compositions/)
Known composition templates and factory references:
- `known_compositions_list.hpp` — Registry of built-in composition types
- `art_reference.hpp` — ART (Adaptive Radix Tree) template
- `hot_reference.hpp` — HOT (Height Optimized Trie) template
- `start_reference.hpp` — START (Self-Tuning Adaptive Radix Tree) template
- `surf_reference.hpp` — SURF (Fast and Compact Prefix Trees) template
- `wormhole_reference.hpp` — Wormhole (Succinct Range Filter) template
- `masstree_reference.hpp` — MassTree (Multi-level Skip List) template

### Builder & Codegen Layer (libs/cache_engine/builder/)
Tooling for automatic permutation and composition generation:
- `anatomy_codegen_tool.hpp` — Orchestration for compile-time and runtime codegen
- `adhoc_emitter.hpp` — Code emission utilities for permutation binaries

## Public API Highlights

### Anatomy Framework
```cpp
namespace comdare::cache_engine::anatomy {
  // Compile-time concept (static dispatch)
  template<typename T> concept AnatomyConcept = /* ... */;
  
  // Runtime virtual interface
  class IAnatomyBase { /* factory + measurement methods */ };
  
  // Genus classification (5 core types)
  enum class AnatomyGenus {
    SearchAlgorithm,  // map-like: std::map, unordered_map, flat_map
    Sequence,         // list-like: std::vector, std::deque, std::list
    Set,              // set-like: std::set, unordered_set, flat_set
    Adapter,          // wrapped view or proxy
    View              // non-owning reference
  };
  
  // Observability
  class IObservableTier { /* measurement hooks */ };
  class IRollbackableTier { /* state save/restore */ };
  class IScannableTier { /* iteration */ };
}
```


## Migration & Usage

### Phase 1: Header-only Consumption (Current)
Import public headers from this module to understand the anatomy framework and composition patterns:
```cpp
#include <comdare-cache-engine-core/anatomy/anatomy_base.hpp>
#include <comdare-cache-engine-core/execution_engine/execution_engine_base.hpp>
#include <comdare-cache-engine-core/abi/anatomy_module_abi_v1.hpp>
```

Build integrates via CMake:
```cmake
find_package(comdare-cache-engine-core REQUIRED)
target_link_libraries(my_app comdare::cache-engine-core)
```

### Phase 2+: Monolith Consumption (Planned, Doku 25)
Future releases will enable direct consumption of the monolith's full anatomy/axes/compositions stack via a **DependencyManager** layer, avoiding ABI brittleness:
- Compile-time axis selection and instantiation
- Seamless integration with custom storage organs
- No dlopen/dlsym overhead for single-binary deployments

See **[Doku 25: Modularization & DependencyManager](../../docs/)** for detailed roadmap.

## Building

**Minimum CMake 3.20**, C++23 capable compiler.

```bash
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake --build .
cmake --install .
```

**Header-only**, no compiled binaries produced. Link as `comdare::cache-engine-core` in downstream projects.

## Dependencies

- **C++23 Compiler** (GCC 13+, Clang 17+, MSVC 17.4+)
