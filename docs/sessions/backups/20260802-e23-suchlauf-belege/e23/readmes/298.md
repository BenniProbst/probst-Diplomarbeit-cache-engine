# comdare-test-system — TEST-INFRA Modul

## Scope

Dieser Modul-Spiegel enthält die **Kern-Test-Infrastruktur** des comdare-cache-engine-Monoliths:

- **GoogleTest-Setup**: FetchContent-basierter automatisierter GTest-Download (v1.15.2) mit Offline-Tarball-Fallback
- **Test-Harness**: `COMDARE_add_test()` CMake-Funktion + ctest-Discovery (PRE_TEST Mode)
- **Prüf-Dock (Pruef-Dock)**: Mess- und Konformitäts-Gate-Infrastruktur für dynamisch geladene Module
  - **conformance_gate.hpp**: std::map-Konformitätstests gegen IDriveableTier-Implementierungen (V5-I4)
  - **pruef_dock.hpp**: ABI-stabiler Mess-Übergangspunkt pro Anatomie-Gattung (SearchAlgorithm/Set/Sequence/Adapter/View)
  - **pruef_dock_registry.hpp**: Registrierung und Verwaltung von Prüf-Dock-Instanzen
  - **pruef_dock_sequencer.hpp**: Sequenzielle Durchführung von Messläufen mit Konformitäts-Gating
  - **search_algorithm_dock.hpp**: Gattungs-spezialisierter Prüf-Dock für SearchAlgorithm-Anatomien
- **Anatomie-Kernel**: Minimale Anatomy-Interfaces für Test-Treibung
  - **idriveable_tier.hpp**: Funktionaler Gattungs-Antrieb (tier_insert/lookup/erase/clear/size, uint64)
  - **anatomy_base.hpp**: AnatomyGenus-Klassifizierung (SearchAlgorithm/Set/Sequence/Adapter/View) + AnatomyConcept Wurzel
  - **measurable_workload.hpp**: ABI-stabiles Workload-Interface für Lastprofil-Treibung
  - **observable_tier.hpp**: Observer-Zugriff (tier_observe → Snapshot-POD) für instrumentierte Messungen
  - **rollbackable_tier.hpp**: Memento-Interface (memento_all) für Zwei-Phasen-Mess-Treiber (V5-I6)
  - **abi_adapter.hpp**: ABI-Adapter-Templates für Module-Loader-Export
- **CMake-Hilfsmittel**: Compiler-Flaggen, Plattform-Erkennung, FetchContent-Stale-Cleanup

**NICHT enthalten**: Fachliche Tests selbst, nur Test-Infrastruktur und Boilerplate-Generator-Funktionen.

## Migrations-Hinweis (Doku 25)

Dieses Modul wird als **READ-ONLY INTERFACE-SPIEGEL** bereitgestellt. Die Quellen bleiben im Monolith unter `libs/cache_engine/` und `cmake/`.

### Konsum des Moduls: DependencyManager-Phase (Folgephase)

In Zukunft können downstream-Projekte dieses Modul über einen **DependencyManager** (`comdare::test-system::gtest`, `comdare::test-system::pruef-dock` etc.) importieren:

```cmake
# Zukünftig (Phase II):
find_package(comdare-test-system REQUIRED COMPONENTS gtest pruef-dock)
target_link_libraries(my_test PRIVATE comdare::test-system::gtest)
```

Aktuell muss der Monolith direkt als add_subdirectory gebaut werden.

### Architektur-Invarianten

- **ABI-Stabilitäts-Garantie**: Die Prüf-Dock-Interfaces (pruef_dock.hpp, conformance_gate.hpp, anatomy_base.hpp) sind ABI-stabil für Modul-Loader-Export
- **Header-Only**: Interfaces sind vollständig inline/template (INTERFACE-Library, kein Linking nötig)
- **Monolith-Deduplikation**: Alle Quellen sind 1:1-Abbilder; Änderungen am Monolith erfordern Spiegelung (aktuell manuell)
