# comdare-search-engine

**Status:** V41.E4.1 (2026-06-01) — Module befuellt mit echtem, kohaerentem Inhalt

Eigenstaendiger Such-Achsen-Modul aus der cache-engine Monolith-Domäne. Exponiert ein kuratiertes Public-Header-Set der Such- und Such-Infrastruktur-Achsen als INTERFACE-Library `comdare::search-engine`.

## Scope

Dieses Modul befasst sich mit den **Such-Achsen** des cache-engine Monolithen:
- **axis_03a** (lookup/search_algo): Lookup-Algorithmen und Such-Strategien (ART, HOT, SURF, B-Tree, Hash, Interpolation, K-ary, Skip List, etc.)
- **axis_03b** (cache_traversal): Cache-Traversal-Strategien (Linear Fanout, Hash Lookup, Binary Search Fanout)
- **axis_04** (node): Node-Type-Strategien fuer Speicher-Knoten-Repräsentation (Node4, Node16, Node48, Node256)
- **axis_02** (path_compression): Path-Compression-Strategien (Byte-wise, Patricia, None)
- **axis_05** (layout): Memory-Layout-Strategien (AoS, SoA, AoSoA, Cache-Line-Aligned, Packed)
- **axis_06** (alloc): Allocator-Strategien (integrierte Schnittstelle fuer 20+ Allokatoren)
- **axis_10** (serialization): Serialisierungs-Strategien (Raw Binary, Compressed, Succinct, Var-Len)
- **axis_14** (value_handle): Value-Handle-Strategien (Inline, External Pool, Versioned Pointer, Chain Ref, Immutable Shared Ref)
- **axis_filter** (filter): Filtermechanismen (Bloom, Cuckoo, XOR, Range SuRF)
- **axis_08** (concurrency): Concurrency-Kontrollstrategien (None, Blocking, Lock-Free, Wait-Free, OLC, RCU, Hazard Pointer)

Keine Hardware/SIMD-spezifischen Achsen (`isa_dispatch`) — diese sind in der `comdare-isa-dispatch`-Domäne.

## Migrations-Hinweis: Monolith-Konsumption via DependencyManager

Die Implementierungen der Such-Achsen sind weiterhin **im cache-engine Monolith** unter `libs/cache_engine/axes/` lokalisiert. Dieses Modul exponiert nur die **öffentlichen Schnittstellen** (Registries, Base-Klassen, Concepts).

**Folgephase (Doku 25+):** 
- VORLAUFIG: Konsumenten der cache-engine linken gegen den Monolith + referenzieren `comdare::search_engine` als Header-Aggregation
- SPÄTER: Ein DependencyManager-Pattern wird etabliert, der die Achsen-Implementierungen zur Ladezeit discovert + registriert (dlopen-basiert, CMake-Plugin-Slot)
- ENDPHASE: Das Modul kann optional als separates Submodule-Repo ausgelagert werden (CMake-Dependency mit gezielter Axis-Subset-Linkerkennung)

Bis dahin: **Kein Funktionalitäts-Break** — das Modul ist ein reiner Header-Spiegel der Monolith-Such-Achsen-Domäne.

## Verwendung

```cpp
#include <comdare-search-engine/lookup/axis_03a_search_algo_registry.hpp>
#include <comdare-search-engine/lookup/concepts/axis_03a_search_algo_concept.hpp>

// Alle bekannten 03a-Strategien uber AllStrategies und EnabledStrategies verfügbar
using SearchStrategies = comdare::cache_engine::lookup::AllStrategies;

// Concept-Prüfung
template <typename S>
concept ValidSearchAlgo = 
  comdare::cache_engine::lookup::concepts::SearchAlgoVariant<S>;
```

## Linken

Als INTERFACE-Library in CMake:

```cmake
target_link_libraries(my_app PRIVATE comdare::search-engine)
```

Das Modul exponiert nur Header-Abhängigkeiten (keine Implementierung). Zur Kompilierung wird gcc/clang >=C++20 benötigt (Concepts, Templates).
