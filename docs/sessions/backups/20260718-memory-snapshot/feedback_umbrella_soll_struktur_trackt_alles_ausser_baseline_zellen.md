**User-Definition (2026-07-07, wortgetreu zusammengefasst, bindend):**

- **Modules-Umbrella** `Projekte/Modules/<familie>-all/` enthaelt: `docs` + `sessions` + `comdare_baseline_N`-Stufen + `module_test_instantiation` (Umbrella-Testsuite aller Module) + **optional** Sprach-Wrapper-Ordner (java/go/python/rust) — **Pflicht**: Baseline-Module; **oder optional** server_oder_client-/Wrapper-Baselines bzw. server+client-Sub-Baselines mit Modulen (Beispiel licensing: client/ + server/).
- **Products** = exakt GESPIEGELTE Struktur, sofern Module instanziiert werden sollen (sonst laufen nur Modultests aus dem Modulcode + die Umbrella-Tests aller Module als Suite).
- **Products-Praezisierung (User 07.07., 2. Runde):** Ein Product ist das AEQUIVALENT eines Modules-Umbrellas (*-all) — dieselben Regeln. **Benennung der Instanziierungs-Module:** `comdare-db-fingerprints`, wenn das Product comdare-db das Modul `comdare-fingerprints` verwendet (Praefix = Product-Name); das Instanziierungs-Modul wird in der **aus Modules KOPIERTEN Baseline im Product** angelegt. **Products duerfen multiple Baselines derselben Layer-Stufe N aus VERSCHIEDENEN Modul-Umbrellas FLACH im eigenen Umbrella anordnen** (z.B. baseline_0 aus foundation neben baseline_0 aus encryption).
- **Tracking-Regel:** Jeder Umbrella trackt ALLES **AUSSER die Baseline-Zellen-INHALTE** — die Baseline-Module sind **eigenstaendige, selbst git-getrackte Repos** und werden **durch CMake als Hot-Dependency frisch gecloned** (spaeter Buildsystem-Automation). Zellen-Inhalte im Umbrella-Index (Voll-Inhalt ODER Gitlink) = Struktur-Fehler.
- **GitLab-Gruppen:** Der Ist-Zustand ueber die GitLab-Gruppen hinweg ist fuer jedes Umbrella **strukturell falsch** angelegt; **die lokale Ordnerstruktur ist das SOLL** (beantwortet die offene B6-Spiegel-Konventions-Rueckfrage).
- **GENERISCHE CLIENT- UND SERVER-MODULE sind first-class (User 08.07., Korrektur meiner Fehlannahme):** Die Matrix kennt **generische client- UND server-Module**. licensing-all ist das kanonische Beispiel: `client/`+`server/`-Buildsystem-Zweige + Baseline-Stack, dessen `comdare-db-client-{ftp,hadoop,iscsi,kafka,nfs,sftp,smb,sql,webdav}` der README EXPLIZIT als **„Base client modules"** (generische CLIENT-seitige DB-Zugriffs-Module) fuehrt, konsumiert vom Client-Stack (comdare-licensing=Client-B+-Lizenzbaum, ***CRED-NAME-REF:***CRED-NAME-REF:comdare-registry******, comdare-keybridge); server-seitig comdare-licensing-server. **NIE solche client/server-Generik-Module als „fehlplatziert" flaggen** (mein #38-Irrtum, zurueckgezogen) — sie sind by design. Einzige generische Frage bleibt Tracking (self-tracked Zelle vs. eingebettet, #274), NICHT thematische Zuordnung.
