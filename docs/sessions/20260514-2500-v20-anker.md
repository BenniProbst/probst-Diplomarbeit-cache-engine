## §2 V20-Designentscheidung

V19 fuehrte `expected_workload` ein (XML-Tag pro Profile, ueberschreibt
traversal-Heuristik in Phase 5). Die Information welcher Workload
tatsaechlich pro Permutation gelaufen ist, geht aber im Export verloren —
sowohl CSV als auch JSON kennen die Spalte nicht.

**V20-Loesung:**
1. `experiment::PermutationResult.workload_used` (string, z.B. "YCSB_F")
2. Phase 5 setzt das Feld pro Permutation, BEVOR aggregator.add(...)
3. ResultAggregator schreibt Spalte in CSV-Header + JSON-Objekt

**Begruendung:** Mess-Auswertung muss reproduzierbar sein. Wenn
expected_workload ein Profile-Override war (V19), muss der Auswertende
das in den Mess-Daten sehen — sonst bleibt das Phasen-Routing intransparent.
